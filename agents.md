# Agent Guidelines: Greg Project Standards

## Core Rules

1. Plain English Only:
   - No fancy words, marketing jargon, or buzzwords anywhere.
   - Use straightforward language in code, comments, logs, UI, and documentation.
   - Example: write "makes it faster" instead of "synergistic velocity enhancement".

2. Punctuation Rules:
   - Never use em dashes (the long dash symbol).
   - Use a regular hyphen (-), colon (:), comma (,), or parentheses where needed.

3. Code Quality:
   - Write clean, straightforward code that looks written by an experienced human engineer.
   - No bloated wrappers, no fake complexity, no vibe coding.
   - Clear variable names, small functions, direct error handling.

4. Greg Decision Philosophy:
   - Cut useless information and marketing fluff.
   - Compare only what actually matters.
   - Give exactly one clear recommendation.
   - If anything is uncertain, state it plainly. Never guess or hallucinate.

5. Commits & Syncing:
   - Use `npm run sync -- "<message>"` to push changes.
   - Keep commit messages short and descriptive without fluff.
